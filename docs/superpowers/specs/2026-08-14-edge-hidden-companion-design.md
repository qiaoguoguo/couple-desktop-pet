# 屏幕边缘微型陪伴与分层反馈设计

## 目标

重新设计桌宠拖到屏幕边缘后的隐藏体验，使桌宠在不遮挡工作的前提下仍然可发现、可拖回，并能完整反馈对方状态、普通消息和“小心意”。

本设计替换左右和下方边缘当前依赖大角色裁切的隐藏形象；上方保留已确认的“双手吊在屏幕上沿”动作。桌宠未贴边时的普通角色、消息卡、状态卡和小心意卡保持现有产品语义。

## 已批准视觉基准

- 微型角色采用“圆脑袋 + 圆眼镜 + 双手扒边”的独立 Q-girl 形象，不再通过裁切完整角色只露头发。
- 左右边缘：完整微型小脸从侧边探出，两只手抓住垂直边缘。
- 下方边缘：小脸正向出现，双手托住下边缘。
- 上方边缘：沿用现有双手悬挂动作及其重力感，不替换为微型探头。
- 左右和下方隐藏待机只播放低频眨眼，不持续摇摆。每次眨眼约 `140ms`，随机间隔 `8–14s`，不连续双闪。
- 角色概念基准：`docs/assets/edge-hidden-micro-mascot-approved.png`。
- 左右和下方方向基准：`docs/assets/edge-hidden-micro-mascot-directions-approved.png`。其中顶部示意不作为实现基准，顶部必须使用现有悬挂资源。

概念图只用于锁定角色身份、比例、眼镜、眼睛、发型、手部姿态和色彩。实现资源必须重新输出为透明 PNG，不能把带背景的概念图直接裁进产品。

## 视觉规格

### 微型角色

- `1.0x` 桌宠比例下，可见角色包围盒高度为 `34px`。
- 随桌宠缩放设置同步变化，计算结果限制在 `30–42px`，避免 `0.6x` 时不可辨认或 `1.45x` 时重新遮挡工作区。
- 圆眼镜和双眼是最优先的小尺寸识别特征；头发高光、衣领和手指细节在小尺寸下允许简化。
- 微型角色必须是完整设计，不得出现孤立发梢、断手、额外人物、边缘脏像素或有色底块。
- 可见角色与实际屏幕边界接触缝隙不得超过 `1` 个物理像素。
- 桌宠进入、退出和拖拽过程中不得显示 WebView、图片或焦点的矩形轮廓。

### 提示卡

提示卡不跟随桌宠缩放，保持 CSS 逻辑像素尺寸，由系统 DPI 正常缩放。卡片锚点跟随微型角色的实际可见包围盒，因此角色缩放后不会与卡片重叠。

- 表面：`#FBFCFA`，不透明度不低于 `0.96`。
- 描边：`1.3px #171715`；小心意使用 `1.5px`。
- 圆角：`7px`。
- 阴影：`0 9px 20px rgba(27, 31, 28, 0.16)`。
- 字体：现有中文字体栈，字距为 `0`。
- 状态卡最小宽度 `126px`，普通消息卡宽度 `224px`，小心意卡宽度 `252px`。
- 文案朝向始终正向；左侧向右、右侧向左、顶部向下、底部向上展开。
- 底部提示必须位于操作系统工作区内，不覆盖任务栏或 Dock。

卡片中的头像、状态和小心意插画必须使用项目透明图片资源。不得用 emoji、Unicode 字符、黄色方块、文字占位或临时 CSS 图形代替语义图标。小心意沿用已批准的黑白清爽包装语言和现有 `heart-surprise` 插画，不使用品牌 Logo。

## 分层反馈

### 安静待机

- 只显示微型角色，不显示文字、底板或常驻气泡。
- 没有未读内容时，鼠标移入只产生最多 `2px` 的向内位移反馈，不切回大角色。
- 左键点击微型角色：退出边缘隐藏，恢复普通桌宠。
- 按住并拖动微型角色：先完成无轮廓退出，再在指针仍按下时开始现有自定义拖拽。
- 右键：退出边缘隐藏后打开现有上下文菜单。

### 对方状态

- 对方上线、离线或活动状态发生变化时，显示轻量状态卡 `3s`。
- 上线推荐文案为“TA 回来啦 / 刚刚上线”；离线文案使用温和表达“TA 先去忙啦”，不制造异常警报感。
- 活动状态沿用现有状态展示词，其中原“敲电脑”语义为“发消息”。
- `3s` 后收成角色旁的状态圆点：在线或活动状态使用薄荷绿，离线使用冷灰蓝。
- 状态圆点表示当前状态，不计入未读数量；下一次状态变化替换旧状态。

### 普通消息

- 收到普通文字消息时，显示头像、单行消息预览和辅助文案，持续 `8s`。
- 预览最多显示一行，超出可用宽度使用省略号，不改变卡片尺寸。
- `8s` 后收成紫灰色未读徽标，显示未读数量，最大显示 `9+`。
- 鼠标移入徽标重新展开当前消息预览；移开后再次收起。悬停预览不得调用现有消息确认逻辑，也不得删除消息。
- 点击徽标或展开卡：退出边缘隐藏并显示现有完整普通消息层，逐字显示和确认语义保持不变。

### 小心意

- 收到小心意时显示插画、情绪标题和辅助文案，持续 `12s`。
- 推荐标题为“有一份心意正在等你”，辅助文案为“点一下，让惊喜慢慢打开”。边缘预览不得出现“外卖”“取件码”“暗号”等直接物流词，也不得提前展示秘密内容。
- `12s` 后收成已有插画体系中的红色心形标记，并持续保留到用户查看。
- 鼠标移入标记重新展开预览；点击后退出边缘隐藏，显示现有折叠小心意卡。用户仍需主动点开后才能看到惊喜暗号。

## 事件调度

- 视觉重要度为“小心意 > 普通消息 > 状态”。任何时刻最多展开一张提示卡。
- 已经展开的消息不被后来状态变化打断。
- 普通消息和小心意继续使用现有远程消息 FIFO，不能为了视觉优先级改变消息顺序、丢弃消息或绕过当前 active message。
- 同一渲染时刻同时出现多个新事件时，先展示小心意，再展示普通消息，最后展示状态；未展示项目保留在各自队列中。
- 当普通消息或小心意处于 active 状态时，状态更新只更新最终状态圆点，不抢占提示卡。
- 边缘进入和退出动画期间到达的事件先记录，稳定进入隐藏待机后再展示。
- 应用窗口被显式隐藏时不弹出边缘提示；重新显示后仍应保留现有未读消息和小心意标记。

边缘提示需要独立的纯状态模型，不能直接改写 `RemoteMessageQueueState` 的 `visible`、`collapsed`、`revealed` 或 `dismissing` 阶段。边缘悬停只是预览，完整消息层仍是确认和揭示行为的唯一所有者。

## 点击查看与自动归位

点击边缘消息或小心意时记录当前边缘、显示器工作区和返回意图：

1. 播放边缘退出动作并把普通桌宠恢复到工作区内。
2. 展示现有完整普通消息或小心意卡。
3. 用户完成现有确认、揭示和关闭流程。
4. 如果用户没有拖动桌宠、打开设置/发送面板、隐藏应用或切换全局点击穿透，则自动回到原边缘并进入微型隐藏待机。
5. 如果显示器或工作区发生变化，按当前显示器重新计算同方向位置；原边缘不可用时停留在安全可见位置。

只有“从边缘提示进入完整内容”设置自动归位意图。普通点击退出边缘、右键菜单、拖拽退出和托盘恢复都不得自动把用户送回边缘。

## 窗口与输入区域

- 边缘隐藏不再依赖把完整角色窗口大面积移出屏幕后进行随机裁切。原生窗口停靠在当前显示器工作区内，专用边缘 stage 只渲染已批准的可见形象。
- 左侧窗口贴工作区左边，右侧贴右边，顶部贴上边，底部贴工作区下边；提示卡全部位于 `320x360` 逻辑舞台的屏幕内侧。
- 透明窗口区域必须继续点击穿透。只有微型角色的 alpha 包围盒、展开提示卡和收起标记注册为 `data-desktop-interactive-region`。
- 微型角色使用基于图片 alpha 的实际包围盒，不得把完整 `320x360` 舞台注册为输入区域。
- 提示卡展开/收起和角色缩放时，交互区域必须逐帧或在布局帧内同步更新，不能出现按钮可见但无法点击的瞬间。
- 全局“点击穿透”开启时，桌宠区域按设置语义全部穿透；用户必须仍能通过托盘“设置”恢复可交互状态，设置勾选值和原生状态保持一致。

Windows 使用现有原生交互区域轮询实现精确穿透。macOS 和 Linux 代码必须保持可编译且不得把 Windows API 泄漏到通用 UI；平台无法提供同等区域命中时使用现有安全回退，不伪装成已支持。

## 状态与模块边界

建议保持两套互不污染的状态：

- `EdgeInteractionState`：负责 `enter / idle / react / exit`、边缘方向、原生停靠和恢复。
- `EdgeNoticeState`：负责状态、消息、小心意的展开、收起标记、计时、未读数量和显示仲裁。

模块职责：

- `pet`：边缘状态机、提示状态机、自动归位意图和纯选择函数。
- `assets`：内置 Q-girl 微型角色透明帧、眨眼帧、方向清单和授权说明。
- `renderer/ui`：边缘微型角色、提示卡和标记，不直接调用 Tauri。
- `desktop`：工作区停靠、恢复、输入区域和多屏几何。
- `sync`：继续拥有远程消息 FIFO 和消息内容，不感知窗口位置。
- `App`：只把当前对方状态和 active remote message 投影为边缘事件，并协调完整内容的打开/关闭。

不得把提示计时、队列排序和 Tauri 命令继续堆进 `App.tsx`。新增行为优先放在纯 reducer/hook 中，并通过已有桌面桥接层调用系统命令。

## 资源清单

新增产品资源至少包括：

- 左右共用的侧向微型角色睁眼透明 PNG；左侧可镜像，但接触锚点必须分别验证。
- 左右共用的侧向微型角色闭眼透明 PNG。
- 下方正向托边睁眼透明 PNG。
- 下方正向托边闭眼透明 PNG。
- 状态圆点或状态图标资源映射，优先复用现有 `status-icons`。
- 普通消息头像资源回退。
- 小心意收起标记使用的透明心形资源，优先复用现有 `heart-surprise.png`。

顶部继续使用现有 `top/enter`、`top/idle`、`top/react` 资源，不重新生成。所有新增图片在黑、白、彩色桌面背景下都要检查 alpha 边缘，并在 `src/assets/README.md` 记录为项目自制/生成资源。

## 异常与回退

- 微型资源预加载失败：取消边缘隐藏并恢复普通桌宠，不显示破图或文字占位。
- 提示图标加载失败：隐藏该图标并保留卡片结构，不显示浏览器破图标。
- 原生停靠失败：恢复安全可见位置并清除边缘状态和自动归位意图。
- 计时器因窗口失焦或系统休眠延迟：恢复时按截止时间计算，不连续补播多张卡。
- 导入角色包没有微型边缘资源：保持普通桌宠，不得回退为内置 Q-girl。

## 验收标准

### 自动化

- 纯状态机测试覆盖进入、退出、低频眨眼调度、3/8/12 秒收起、悬停重展、事件仲裁和未读 `9+`。
- 测试证明边缘预览不会改变远程消息阶段，普通消息和小心意仍按现有 FIFO 推进。
- App 集成测试覆盖隐藏时收到状态/普通消息/小心意、点击查看、关闭后归位和用户拖动后取消归位。
- 渲染测试覆盖只有可见角色、标记和卡片拥有交互区域，透明舞台不阻挡点击。
- Rust 几何测试覆盖四边、负坐标副屏、任务栏工作区、100%/125%/150% DPI 和显示器变化。
- 现有消息、小心意、状态、点击穿透、设置、拖拽和边缘测试全部通过。

### 原生视觉与交互

- 在黑、白和复杂桌面背景下检查左右、上、下四边。
- 在 `0.6x`、`1.0x`、`1.45x` 检查角色尺寸、卡片锚点和输入区域。
- 验证左右和下方是完整微型角色，上方仍是现有双手悬挂。
- 验证低频眨眼不形成持续干扰，提示无黄色方块、emoji、文字图标或矩形底色。
- 验证卡片外透明区域可点击桌面，角色和卡片可拖、可点，拖动过程没有正方形线框。
- 验证状态 `3s`、消息 `8s`、小心意 `12s` 后分别收成正确标记，悬停可重展。
- 验证点击消息/小心意后显示完整内容，关闭后回原边缘；主动拖动后不自动归位。
- 构建 debug EXE，并在真实 Windows 桌面运行最终截图验收。

## 非目标

- 不修改 Relay 协议、配对流程、小心意载荷或服务器部署。
- 不为导入包自动生成或盗用边缘资源。
- 不重做普通桌面状态卡、消息卡和小心意揭示卡。
- 不在本任务中实现 macOS/Linux 新的原生区域命中能力；只保持模块边界、编译和现有回退行为。
