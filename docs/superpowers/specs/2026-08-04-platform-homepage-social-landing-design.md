# Platform Homepage Social Landing Design

## Goal

将当前 `platform-web` 首页从“内测管理入口”改成具备情绪价值的消费级官网首页，选用第 3 张效果图方向：以“每天见一面，屏幕也会变温柔”为核心，主打情侣/好友桌宠的陪伴仪式、消息互动、连续互动天数和后续轻社交排行榜。

## Current Functional Surface

当前平台已有能力：

- 首页：基础内测平台说明。
- 邀请码：输入邀请码并验证。
- 注册：邀请码验证后填写邮箱、昵称、密码完成注册。
- 登录：邮箱密码登录。
- 下载：登录后查看 Windows 内测包并下载。
- 管理后台：管理员查看用户、邀请码、设备、版本和下载记录。
- 后端接口：邀请码、注册登录、设备登记、版本发布、认证下载和下载事件记录。

当前缺口：

- 没有真正面向用户转化的官网首页。
- 没有产品情绪表达和场景化视觉。
- 没有展示后续“上传参考图生成 Q 版桌宠资源包”的能力路径。
- 没有把连续互动天数、轻社交排行榜包装成用户愿意期待的产品价值。

设计关键词：

- 温暖、可爱、轻社交、陪伴仪式。
- 不做企业后台，不做冷冰冰下载站。
- 排行榜要表达“暖心陪伴”，不能让用户产生打卡压力。
- 首页第一屏展示双屏桌宠串门、消息气泡和 `连续互动 27 天` 预览。
- 保留下载和内测注册路径，降低用户进入门槛。

## Homepage Content

首屏：

- 品牌名：`情侣桌宠`
- 导航：`桌宠互动`、`形象工坊`、`连续天数`、`下载`、`登录`
- 主标题：`每天见一面，屏幕也会变温柔`
- 副文案：`下载桌面端，导入彼此的小人。消息、串门和连续互动，让陪伴变成可看见的日常。`
- 主按钮：`加入内测`
- 次按钮：`先下载体验`
- 平台提示：`Windows 内测中 · 后续支持 macOS / Linux`
- 视觉重点：两个屏幕/窗口里的 Q 版桌宠互相串门，消息气泡和 `连续互动 27 天` 预览。

首屏下方露出：

- `绑定好友`
- `互发消息`
- `桌宠串门`
- `互动天数`

第二段产品能力：

- `自由捏造属于你们的小人`
- 展示未来链路：`上传参考图` -> `生成多版 Q 版形象` -> `选择喜欢版本` -> `下载资源包` -> `导入桌面端`
- 明确这属于后续能力，不在当前 API 中假装已完成。

下载/账号入口：

- 登录后继续展示真实 Windows 版本下载表。
- 未登录下载时进入登录/邀请码注册路径。
- 管理后台入口保留，但视觉上从主导航弱化，避免普通用户把官网误认为管理系统。

## UX Rules

- 首页不能被管理后台表格主导。
- 首页主路径是 `加入内测`，辅助路径是 `先下载体验`。
- 普通用户导航不要突出 `管理后台`；管理员入口可在登录后或页脚出现。
- 不新增真实付费、AI 生成、排行榜 API；这轮只做官网表达和前端交互壳。
- 后续 AI 生成资源包的入口可以展示为“即将开放/预约体验”状态。
- 不使用版权不明的人像或第三方角色素材。

## Visual Rules

- 色彩：暖奶油底、珊瑚红主按钮、少量青色/黄油色点缀、深棕文字。
- 字体：中文可读性优先，标题可偏手写但正文必须清晰。
- 圆角：按钮和功能项不超过 8px。
- 图片资产：需要真实生成的 hero/桌宠插画资产，不用 CSS 画假图。
- 不使用紫蓝渐变、抽象光球、深色 SaaS 仪表盘、过度 KPI 卡片。

## Non-Goals

- 不实现真实 AI 生图服务。
- 不实现资源包云端生成队列。
- 不实现真实排行榜后端。
- 不修改桌面端导入资源包逻辑。
- 不改部署端口和服务器配置。

## Validation

- `pnpm platform-web:test`
- `pnpm platform-web:typecheck`
- `pnpm platform-web:build`
- `pnpm typecheck`
- 本地运行 `pnpm platform-web:dev` 后检查首页、登录、邀请码、下载和管理后台路由仍可进入。
