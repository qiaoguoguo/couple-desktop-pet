# 主窗口对方状态卡与趣味状态同步设计

## 背景

当前版本使用 `peer-presence`、`peer-link` 和 `offline-nest` 三个透明卫星窗口展示对方在线状态。实际体验中，这套表现层过重，透明窗口的布局、点击穿透和合成行为也增加了维护成本。

本设计用主窗口内的单个轻量状态卡取代卫星窗口。状态卡不仅表达在线和离线，还承载用户主动选择的趣味状态，例如“摸鱼中”“发呆中”和“加班中”。

本设计取代 `2026-08-06-peer-presence-multi-window-fidelity-design.md` 中的卫星窗口展示方案。角色包中的在线、离线头像字段继续保留并复用。

## 目标

1. 在桌宠主窗口内直观展示对方当前状态。
2. 不再创建任何状态卫星窗口、动态连线或离线小窝。
3. 用户可以从现有六个环形功能按钮进入“我的状态”选择器。
4. 手动选择的趣味状态通过现有一对一 WebSocket 连接实时同步给对方。
5. 状态定义可继续扩展，而无需修改状态卡结构或把状态伪装成聊天消息。

## 非目标

- 不自动检测前台应用、键盘、鼠标或工作时长。
- 不允许用户输入自由状态文本。
- 不将趣味状态写入互动数据后台或排行榜。
- 不恢复公共匹配或多人状态广播。
- 不在本阶段增加状态历史、统计或定时切换。

## 状态模型

连接状态与趣味状态分开建模：

- 连接状态：`unknown`、`online`、`offline`。
- 本地趣味状态：`null`、`slacking`、`dazing`、`overtime`。
- `null` 表示未选择趣味状态，对方在线时显示普通“在线”。

首版状态定义：

| 状态 ID | 主文案 | 辅助文案 | 语义 |
| --- | --- | --- | --- |
| `null` | TA 在线 | 正在陪你 | 清除手动状态后的默认在线状态 |
| `slacking` | TA 摸鱼中 | 偷偷歇一会 | 用户手动选择 |
| `dazing` | TA 发呆中 | 灵魂出走啦 | 用户手动选择 |
| `overtime` | TA 加班中 | 努力搬砖中 | 用户手动选择 |

状态显示优先级：

1. 未绑定时不显示状态卡。
2. 已绑定但 Relay 尚未给出对方在线信息时，显示“正在寻找TA / 连接恢复后告诉你”。
3. 对方离线时始终显示“TA 离线 / 等TA回来”，忽略缓存的趣味状态。
4. 对方在线且存在趣味状态时显示对应趣味状态。
5. 对方在线且不存在趣味状态时显示普通在线状态。

状态 ID 使用 TypeScript 字面量联合和共享协议校验。增加新状态时只扩展状态目录、选择器选项和文案映射。

## 主窗口界面

### 状态卡

状态卡位于主窗口内、桌宠上方偏右区域，参考用户提供的紧凑白色状态框：

- 目标尺寸约 `164 x 60px`，在 320 x 360 主窗口内固定布局。
- 使用半透明暖白背景、12px 以内圆角、单层浅边框和轻阴影。
- 左侧为 28px 对方头像；在线优先使用 `portrait`，离线优先使用 `offlinePortrait`，继续沿用现有头像回退链。
- 中间第一行为状态圆点和主文案，第二行为辅助文案。
- 右侧为对应状态的小型圆形图标。
- 状态卡不响应点击，使用 `pointer-events: none`，避免影响桌宠拖拽和单击菜单。
- 文案必须在固定宽度内截断或压缩，不得撑大主窗口。

视觉状态使用克制的多色区分：

- 在线：珊瑚红状态点和心形图标。
- 离线：蓝灰状态点和月亮图标。
- 摸鱼中：水绿色状态点和休息图标。
- 发呆中：浅紫状态点和云朵图标。
- 加班中：琥珀色状态点和公文包图标。
- 连接中：中性灰状态点和旋转中的加载图标。

仅连接中图标允许连续旋转。其他状态切换使用 180 至 240ms 的淡入和轻微位移，不缩放整个透明窗口，也不使用多层发光效果。

### 显示与避让

以下情况暂时隐藏状态卡：

- 设置页打开。
- 消息输入面板打开。
- 收到远程消息并播放互动场景。
- 六按钮环形菜单或状态选择器打开。
- 桌宠处于边缘半隐藏模式。

普通待机、行走和本地动作期间可继续显示状态卡。状态卡不改变主窗口尺寸。

### 状态选择器

现有六个环形功能按钮保持六个槽位：

- “敲电脑”继续作为发送消息入口。
- 当前“困困打盹”槽位改为“我的状态”。

点击“我的状态”后关闭一级环形菜单，并在主窗口内显示一个紧凑的二级状态选择器。首版提供：

- 在线：清除手动趣味状态。
- 摸鱼中。
- 发呆中。
- 加班中。

选中后立即关闭选择器、保存本地设置并尝试同步。按 `Escape`、单击选择器外部或右键打开设置时关闭选择器，不修改状态。

## 本地设置

在同步设置中增加：

```ts
activityStatus: "slacking" | "dazing" | "overtime" | null;
```

要求：

- 默认值为 `null`。
- 通过现有设置归一化和持久化流程读写。
- 取消绑定时保留用户选择，重新绑定或重连后继续同步。
- 选择成功不依赖对方在线；对方不在线时先保存在本地，下一次连接后发送。

## 实时协议

趣味状态使用独立协议消息，不复用聊天消息。

客户端到服务端：

```ts
{
  type: "status.update";
  requestId: string;
  pairId: string;
  activityStatus: "slacking" | "dazing" | "overtime" | null;
}
```

服务端到对方客户端：

```ts
{
  type: "peer.status";
  pairId: string;
  peerDeviceId: string;
  activityStatus: "slacking" | "dazing" | "overtime" | null;
  changedAt: string;
}
```

同步规则：

1. 客户端收到 `auth.ok` 后发送当前本地趣味状态。
2. 用户修改状态后立即发送 `status.update`。
3. Relay 校验配对关系和状态 ID，只在当前一对一配对内转发。
4. Relay 在当前连接记录中保存状态值，不写入数据库。
5. 后连接的一方认证成功时，Relay 将已在线一方当前连接中的状态随 `peer.status` 补发。
6. 对方离线后，客户端保留收到的最后状态值，但界面由离线状态覆盖。
7. 对方重新上线但尚未收到状态时先显示普通在线，收到 `peer.status` 后切换。

`RealtimeClient` 增加 `setActivityStatus` 方法。发送失败不阻断聊天和在线状态；客户端保留本地选择，并在下一次认证成功后重发。

## 服务端兼容与部署

- 新 Relay 接受旧客户端不发送状态消息，默认趣味状态为 `null`。
- 新客户端仍可完成认证和聊天；趣味状态功能要求 Relay 更新后才能生效。
- 修改共享协议、Relay 连接注册表和 WebSocket 转发测试。
- 客户端和 Relay 验证通过后，将新 Relay 构建部署到现有远程服务器，并重启现有服务。
- 不修改配对、消息发送、账号或数据库结构。

## 旧卫星方案清理

删除或解除以下运行时能力：

- 主窗口对 `update_companion_scene`、`hide_companion_scene` 的调用。
- `peer-presence`、`peer-link`、`offline-nest` WebView 创建与事件桥接。
- 卫星窗口 React 根组件、状态协调器和只服务于连线/离线小窝的 UI 素材。
- Rust 命令注册和伴随窗口生命周期代码。

保留：

- 角色包 `portrait`、`offlinePortrait` 字段及其导入校验。
- 对方角色包映射和头像回退逻辑。
- 已有一对一在线状态和消息能力。

旧设计文档和历史提交保留，作为架构决策记录。

## 异常处理

- 未配对：不显示状态卡，也不允许发送状态。
- Relay 未连接：本地选择仍保存，UI 对对方显示“正在寻找TA”。
- 状态发送失败：不弹阻塞对话框；使用短气泡提示“状态已保存，连接后会同步”。
- 收到未知状态 ID：按 `null` 处理并显示普通在线，不能直接渲染服务端文本。
- 对方头像加载失败：依次回退到预览图、默认动作首帧和“TA”文字占位。
- 取消绑定：清空运行时对方状态，不删除本地选择。

## 测试与验收

### 前端

- 状态优先级映射单元测试。
- 状态卡在线、离线、连接中和三种趣味状态渲染测试。
- 状态卡在设置、消息、远程场景、菜单和边缘模式下的隐藏测试。
- “我的状态”入口、选择、取消、持久化和断线保存测试。
- 头像回退和未知状态降级测试。
- 断言主应用不再调用卫星窗口命令。

### 实时客户端与共享协议

- `status.update` 和 `peer.status` 解析、拒绝未知状态及长度边界测试。
- 认证成功后自动同步当前状态测试。
- 修改状态即时发送、断线失败后重连重发测试。
- `useRealtimeSync` 保存和清理对方趣味状态测试。

### Relay

- 只向已配对且在线的对方转发状态。
- 拒绝错误 `pairId` 和未知状态。
- 后上线客户端能收到已在线一方当前状态。
- 状态更新不产生聊天消息或送达回执。
- 旧客户端不发送状态时保持现有在线、离线和消息行为。

### 桌面端

- Windows 实机确认只存在主窗口和托盘，不创建三个状态卫星窗口。
- 320 x 360 主窗口中状态卡不裁切、不遮挡桌宠脸部和环形菜单。
- 状态切换没有黑底、残影或窗口尺寸跳变。
- 双客户端通过远程 Relay 验证离线、普通在线和三种趣味状态同步。
- 验证消息发送、收到消息确认、拖拽、边缘半隐藏、设置和退出没有回归。

## 交付物

- 扩展后的共享 WebSocket 协议、实时客户端和 Relay。

- 更新后的远程 Relay 服务。

- 自动化测试结果和在线、离线、趣味状态实机截图。
