# 桌宠交互与长动画重设计

日期：2026-08-02

状态：待用户复核后进入实施计划阶段

## 背景

当前本地桌宠 MVP 已能展示透明窗口、生成的星星睡衣桌宠序列帧、设置面板、拖拽、右键菜单和托盘菜单。但现有体验仍偏工程样机：

- 单击桌宠只触发固定开心反馈，交互方式太单一。
- 动画资源只有 2-6 帧，多数动作时长不足 1 秒，播放时不连贯。
- 待机动画只有短循环，缺少自然变化。
- 设置和系统菜单已经存在，但用户缺少面向桌宠本体的互动选择入口。

本 spec 只重做本地桌宠交互与动画，不引入联网、匹配、消息、语音、AI、资源包导入、商店或账号系统。

## 目标

1. 单击桌宠弹出互动选项菜单，而不是直接触发单一开心动作。
2. 新增多种可选互动动作，至少包含用户指定的“撒娇卖萌”和“敲电脑”。
3. 每个互动动作动画时长至少 5 秒。
4. 待机动画重新设计为多段随机待机，每段也至少 5 秒。
5. 重新生成星星睡衣桌宠动作帧资源，提高动作连贯性和角色一致性。
6. 保持本地 MVP 架构边界：交互状态、动画清单、资源文件和 UI 菜单职责清晰。

## 非目标

- 不做远程互动、串门、聊天或语音。
- 不做 Live2D。
- 不做复杂物理或骨骼动画。
- 不做用户导入资源包。
- 不把第三方版权不明素材加入仓库。
- 不改变右键系统菜单和托盘系统菜单的基本职责。

## 交互入口

### 单击桌宠

单击桌宠时打开“互动选项菜单”。菜单是桌宠本体交互入口，和右键系统菜单分开。

菜单行为：

- 出现在桌宠附近，默认不遮挡桌宠脸部。
- 包含 6 个互动按钮。
- 点击某个互动后，菜单关闭并播放对应动作。
- 再次单击桌宠可重新打开菜单。
- 点击菜单外或按 `Escape` 关闭菜单。
- 动作播放期间再次单击可以打开菜单，但选择新动作会中断当前动作并播放新动作。
- 拖拽时不打开互动菜单，避免和窗口移动冲突。

### 右键桌宠

右键仍打开系统菜单：

- 设置
- 重置位置
- 隐藏
- 退出

右键菜单不承载卖萌、敲电脑等桌宠互动动作。

### 托盘菜单

托盘菜单继续用于系统控制：

- 显示
- 隐藏
- 设置
- 退出

点击穿透开启后，用户仍可通过托盘“设置”恢复交互能力。

## 互动动作

第一版新增 6 个互动动作。

| 动作 ID | 显示文案 | 动画意图 | 气泡文案 | 时长 |
| --- | --- | --- | --- | --- |
| `act-cute` | 撒娇卖萌 | 身体左右轻晃，脸颊更红，眼睛亮起来，帽尖小星星轻轻摆动 | “陪我一会儿嘛。” | 6 秒 |
| `act-typing` | 敲电脑 | 变出小小键盘或迷你电脑，认真敲几下后抬头看用户 | “我也在努力敲代码。” | 6 秒 |
| `act-wave` | 打招呼 | 抬起星星袖口挥手，身体微微前倾 | “嗨，我在这里！” | 5.5 秒 |
| `act-hug` | 求抱抱 | 张开两边星星袖口，向前小跳，最后停在期待表情 | “可以抱一下吗？” | 6 秒 |
| `act-pout` | 生气鼓脸 | 脸颊鼓起，眼睛瞥向一边，帽尖小星星抖一下 | “哼，快哄我。” | 5.5 秒 |
| `act-drowsy` | 困困打盹 | 眼睛慢慢闭上，身体下沉，最后小小惊醒 | “有点困啦。” | 6 秒 |

动作规则：

- 所有互动动作都是非循环动作。
- 动作完成后回到随机待机。
- 动作播放中允许拖拽，拖拽优先级最高。
- 动作播放中如果打开系统设置面板，不继续弹互动菜单。

## 待机动画

待机不再只有单一 `idle`。改为 3 组随机待机动画：

| 动作 ID | 显示含义 | 动画意图 | 时长 |
| --- | --- | --- | --- |
| `idle-breathe` | 轻呼吸 | 轻微上下呼吸，眼睛偶尔眨一下，帽尖小幅摆动 | 6 秒 |
| `idle-look` | 看星星 | 眼睛看向帽尖小星星，小星星轻摆，表情安静 | 6 秒 |
| `idle-stretch` | 小伸懒腰 | 身体稍微伸展，两边星星袖口展开后回落 | 6 秒 |

待机调度规则：

- 空闲状态下随机选择一组待机动作播放。
- 每段待机播放完整后再选择下一段。
- 用户交互、拖拽、自动移动、睡眠会打断待机。
- 随机选择需要避免连续三次播放同一组待机。

## 其他基础动作

保留但重做以下动作资源：

| 动作 ID | 说明 | 时长 |
| --- | --- | --- |
| `walk` | 自动移动时播放，身体左右轻摆，小步移动感更明显 | 5 秒以上循环 |
| `drag` | 拖拽时播放，身体被拎起或轻微晃动 | 5 秒以上循环 |
| `sleep` | 长时间无交互后播放，闭眼呼吸和帽尖轻晃 | 6 秒循环 |

## 动画帧规格

为保证连贯性和工作量可控，第一版采用统一帧策略：

- 每个动作 18 帧。
- 默认帧率 3 fps。
- 单个动作时长 6 秒。
- `act-wave` 和 `act-pout` 如需稍短，可使用 17 帧 / 3 fps，仍必须超过 5 秒。
- 所有帧尺寸统一为 512x640 源图，经透明处理后仍保持同一画布比例。
- 前端显示时继续缩放到当前桌宠窗口内。
- 动作帧命名使用两位序号，例如 `act-cute-01.png` 到 `act-cute-18.png`。

预计资源量：

- 3 组待机：54 张
- 6 组互动：108 张
- 3 组基础动作：54 张
- 总计约 216 张 PNG

这是可接受的本地 MVP 资源量，但实施时应先生成 `idle-breathe` 和 `act-cute` 两组作为质量基准，通过后再批量生成其余动作。

## 资源生成策略

角色仍为“星星睡衣小星人”，基于用户提供参考图和现有项目生成角色，不复制原图像素。

生成流程：

1. 先生成新的标准姿态基准图 `character-base.png`。
2. 以“用户原参考图 + `character-base.png`”作为所有动作帧参考。
3. 每组动作先生成 3 张关键帧草案：起始、中段、结束。
4. 质量通过后，再按该组完整 17-18 帧生成。
5. 所有输出先使用纯色 chroma-key 背景。
6. 本地去除背景，输出透明 PNG。
7. 检查透明角、角色边缘、绿色溢色、尺寸和小尺寸可读性。

统一提示词约束：

- 手绘蜡笔儿童插画质感。
- 黄色星形睡衣/帽子，橙色圆脸，大眼睛内有星星高光，红脸颊，小微笑。
- 保持同一角色比例、颜色、脸部特征、线条质感和画布位置。
- 桌宠在 128px 高度下仍能读出动作。
- 无水印、无文字、无额外角色。
- 除 `act-typing` 可出现小键盘或迷你电脑外，不加入无关道具。

## 前端数据模型

将动画动作从旧的简单 `PetActionName` 扩展为稳定 action id：

```ts
type PetActionName =
  | "idle-breathe"
  | "idle-look"
  | "idle-stretch"
  | "walk"
  | "drag"
  | "sleep"
  | "act-cute"
  | "act-typing"
  | "act-wave"
  | "act-hug"
  | "act-pout"
  | "act-drowsy";
```

`PetActionDefinition` 增加建议字段：

```ts
interface PetActionDefinition {
  fps: number;
  loop: boolean;
  frames: readonly string[];
  durationMs: number;
  category: "idle" | "movement" | "interaction";
}
```

互动菜单使用独立清单：

```ts
interface PetInteractionOption {
  id: PetActionName;
  label: string;
  bubble: string;
}
```

## 状态机和调度

状态机需要新增 `interacting` 状态，记录当前互动动作：

```ts
type PetStateName =
  | "idle"
  | "walking"
  | "dragging"
  | "interacting"
  | "sleeping";
```

新增事件：

- `INTERACTION_SELECTED`
- `IDLE_ANIMATION_FINISHED`

规则：

- `INTERACTION_SELECTED` 进入 `interacting`，并记录 action id。
- `interacting` 播放完成后回到 `idle`。
- `idle` 完成当前待机动画后选择下一段待机。
- `dragging` 优先级最高，会打断互动和待机。
- `sleeping` 被单击时先打开互动菜单，不自动直接切互动动作。
- 自动移动仍只在空闲时触发。

## UI 设计

互动菜单使用轻量浮层，不做营销式面板。

菜单要求：

- 2 列按钮，每个按钮有短文案。
- 按钮尺寸稳定，文案不换行溢出。
- 菜单圆角不超过 8px。
- 不遮挡桌宠主体脸部，优先贴近下方或侧边。
- 点击外部、按 `Escape`、选择动作后关闭。
- 不使用常驻说明文字。

## 错误处理

- 某个动作帧缺失时，该动作不显示在互动菜单中，并记录为开发错误。
- 当前动作加载失败时回退到 `idle-breathe`。
- 如果 `idle-breathe` 也缺失，才显示开发占位 fallback。
- 批量资源生成失败时，不使用版权不明的网络素材替代。

## 测试和验证

自动化测试至少覆盖：

- 单击桌宠打开互动菜单。
- 选择互动项后菜单关闭并进入对应动作。
- 互动动作 5 秒以上完成后回到待机。
- 待机动作能在多组之间切换，且避免连续三次同一待机。
- 右键系统菜单仍可打开设置、重置位置、隐藏、退出。
- 拖拽不打开互动菜单。
- 点击穿透开启时设置面板不会锁住窗口。
- manifest 中所有动作帧存在，且每个互动动作 `durationMs >= 5000`。

手工验收至少覆盖：

- 单击桌宠能弹出互动选项。
- 6 个互动动作都可播放，且每个动作明显超过 5 秒。
- 待机时能看到不同待机动作随机切换。
- 动画播放不明显跳帧、不突然变形、不出现绿色边缘。
- 小尺寸下仍能看清角色表情和动作。
- 右键系统菜单和托盘菜单不回归。

## 实施顺序

1. 修复已发现的点击穿透锁住设置面板问题。
2. 建立新的动作模型和互动菜单，但先复用旧资源或临时资源让测试跑通。
3. 生成 `character-base.png`、`idle-breathe` 和 `act-cute` 作为质量基准。
4. 通过视觉检查后批量生成其余动作帧。
5. 接入完整 manifest。
6. 跑自动化验证和 Windows 手工验收。

## 风险和取舍

- 216 张 PNG 会增加仓库体积，但本地 MVP 可以接受；后续资源包系统再处理按需加载和外置资源。
- AI 批量生成可能造成角色细节漂移，所以必须先用标准姿态基准图锁定身份。
- 18 帧 3 fps 比高帧率更适合当前生成式资源工作流；如果后续改 Live2D 或骨骼动画，再提高运动平滑度。
- `act-typing` 需要小键盘或迷你电脑道具，这是唯一允许的动作道具例外。
