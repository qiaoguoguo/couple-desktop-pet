# 远程桌宠消息互动设计

## 背景

当前远程消息收到后主要通过本地气泡或设置页消息列表呈现。气泡自动消失时间很短，用户容易错过；设置页里的消息列表也不像桌宠之间的互动，更接近普通聊天弹窗。新的交互目标是让消息看起来像“对方桌宠来访并说话”，并且收到的消息必须经过用户轻量确认后才消失。

## 目标

- 收到对方消息时，在桌宠窗口内显示对方桌宠形象。
- 对方消息以对方桌宠的对话气泡呈现，不使用系统弹窗或设置页弹窗作为主要入口。
- 收到的消息默认保持可见，鼠标滑过对方桌宠或消息气泡后才视为确认。
- 确认后短暂延迟再隐藏，避免鼠标误触导致瞬间消失。
- 保留设置页消息历史，但它只作为历史记录和调试入口。
- 第一版不强制扩展资源包格式，不要求所有资源包生成双人互动帧。

## 非目标

- 不实现多人会话。
- 不实现完整聊天窗口。
- 不引入账号系统、头像上传或云端资源分发。
- 不在本轮生成新的双人互动动作帧。
- 不让远程消息触发任何远程电脑控制能力。

## 推荐方案

采用运行时组合方案：本机桌宠照常显示；收到远程消息时，前端解析发送方设备对应的宠物资源包，并在本机桌宠旁边渲染一个小型“来访桌宠”。来访桌宠使用该资源包的 `idle` 动画首帧或预览图作为形象，旁边显示消息气泡。

如果已经在设置中为该设备关联了对方资源包，则使用该资源包。如果没有关联资源包，则显示一个明确的轻量占位形象和“对方桌宠”标签，避免破图或空白。

消息生命周期分为四个阶段：

1. `visible`：收到消息后立刻显示，持续保留。
2. `hovered`：用户鼠标移入来访桌宠或气泡区域，视为已读确认。
3. `dismissing`：确认后保留约 800ms，让用户知道已经完成互动。
4. `hidden`：隐藏当前消息。如果有排队消息，显示下一条。

## 组件边界

### `sync`

远程消息仍然由现有实时同步模块接收，不把 UI 呈现逻辑写入同步客户端。同步模块只负责提供 `fromDeviceId`、`text`、`at` 等事件数据。

### `assets`

资源包解析逻辑继续负责把资源包 ID 解析为可渲染的图片 URL。新增对“对方设备资源包”的读取使用现有 `settings.appearance.peerPetPackageByDeviceId` 映射，不改变 `.cdpet` 包格式。

### `bubble` / `pet`

普通本地提示气泡继续用于本机状态、自己发送消息后的短提示等场景。远程消息互动建议新增独立的 `RemoteMessageLayer`，避免把远程确认生命周期塞进普通 `BubbleLayer`。

### `ui`

设置页继续展示消息历史、绑定状态和资源包选择。收到消息时不强制打开设置页，不让设置页挡住桌宠互动。

## 数据结构

新增前端状态可以保持在 `App` 附近，后续再抽出 store：

```ts
type RemoteMessageCard = {
  id: string;
  fromDeviceId: string;
  text: string;
  at: number;
  state: "visible" | "hovered" | "dismissing";
};
```

如果连续收到多条消息，第一版采用先进先出的队列。当前消息未确认时，新消息进入队列，不覆盖当前可见消息。

## 交互细节

- 来访桌宠显示在本机桌宠旁边，优先放在右侧；窄窗口或边界不足时使用 CSS 约束保持在窗口内。
- 气泡最大宽度受控，长文本自动换行。
- 鼠标移入来访桌宠或气泡区域后触发确认，不要求点击。
- 确认后区域进入轻微淡出状态，约 800ms 后消失。
- 如果没有鼠标滑过，消息保持显示，不因定时器自动消失。
- 自己发送的消息可以继续使用短气泡反馈，但显示时间应延长到约 5 秒，并且不影响收到消息的持久显示。
- 设置页消息列表保留时间戳和方向，不作为消息确认依据。

## 测试策略

- 单元测试：收到远程消息后显示消息文本和对方形象区域。
- 单元测试：远程消息不会因为短定时器自动消失。
- 单元测试：鼠标滑过消息区域后进入确认流程，并在延迟后隐藏。
- 单元测试：未关联对方资源包时使用占位形象，不显示破图。
- 单元测试：连续两条远程消息按队列逐条确认。
- 回归测试：自己发送消息仍调用实时同步发送接口。
- 回归测试：普通本地气泡仍可用于非远程提示。

## 验收标准

- 收到对方消息时能看到对方桌宠形象和消息气泡。
- 消息不会在用户未确认前自动消失。
- 鼠标滑过来访桌宠或气泡后，消息确认并在短延迟后消失。
- 连续消息不会覆盖未确认消息。
- 没有导入对方资源包时界面仍然可用，不出现破图。
- 设置页不再承担主要消息弹出职责。
- `pnpm test`、`pnpm typecheck` 通过。
- 如涉及 Tauri 构建，`pnpm tauri build --debug` 通过。

## 后续扩展

后续可以在资源包规范中增加可选的 `duoActions` 字段，用于描述牵手、拥抱、拍肩、一起敲电脑等双人互动序列帧。该能力应保持可选：旧资源包不提供双人帧时仍使用运行时组合方案。

## 自检

- 范围聚焦在远程消息呈现和确认生命周期，没有扩展到完整聊天系统。
- 没有要求本轮修改资源包格式，因此不会破坏现有导入包。
- 对无对方资源包的情况定义了占位降级。
- 对连续消息、未确认消息和确认后隐藏都给出了明确行为。
