# 情侣小心意消息设计

日期：2026-08-12

## 背景

当前情侣桌宠已经支持一对一绑定、在线状态和文字消息。用户可以通过环绕菜单打开消息输入面板，对方收到后会看到桌宠动画和逐字消息气泡。

本功能复用现有文字通信链路，增加一种有仪式感的结构化消息：发送者在外卖平台完成下单，送达后通过桌宠发送心意主题、惊喜暗号和留言。接收者先看到一张情绪化提醒卡，主动点开后才看到惊喜暗号，最后点击“我收下啦”关闭。

这不是外卖平台接入。桌宠不处理商品选择、地址、支付、订单查询或配送状态。

## 目标

- 用专属入口和卡片把普通文字提升为有仪式感的情侣互动。
- 覆盖道歉、哄人、生日、节日、想念和日常惊喜等常见情境。
- 接收端只表达心意和关系，不出现“外卖”“订单”“配送”“取件码”等物流语言。
- 复用现有 `message.send` / `message.received` 通信链路，不新增数据库或独立业务服务。
- 新旧客户端和新旧 Relay 混用时至少能收到一条可读的普通文字消息。
- 保持本地桌宠核心、桌面窗口能力、消息协议和 UI 组件之间的现有边界。

## 非目标

- 不接入美团、饿了么、鲜花或礼物平台。
- 不在桌宠内完成下单、支付、地址选择或订单追踪。
- 不识别短信、通知或剪贴板中的取件信息。
- 不回传“已查看”“已收下”或领取结果。
- 不做离线消息存储；对方离线时沿用当前发送限制。
- 不实现端到端加密；结构化内容沿用现有 Relay 消息的传输安全边界。
- 不增加排行榜、连续送礼天数或运营统计。

## 已确认入口

环绕菜单继续保持六个入口：

1. `撒娇卖萌`
2. `发消息`
3. `打招呼`
4. `求抱抱`
5. `外卖到啦`
6. `我的状态`

具体变更：

- 原 `敲电脑` 只改显示文案为 `发消息`，普通文字消息能力不变。
- `外卖到啦` 占用原 `生气鼓脸` 的菜单位置。
- `act-pout` 动作和资源不从资源包契约中删除，只是不再作为内置环绕菜单入口。
- `外卖到啦` 是发送者理解功能用途的入口名称；接收者界面不显示该词。

未绑定、Relay 未连接或对方离线时，`外卖到啦` 与 `发消息` 使用相同的可用性判断和错误反馈，不打开不可发送的表单。

## 发送流程

### 窗口行为

- 点击 `外卖到啦` 后关闭环绕菜单，并打开主窗口内的专属发送面板。
- 复用当前消息编辑器的临时窗口模式：保存桌宠原位置，将窗口移到当前显示器工作区中央，关闭后恢复原几何位置。
- 普通消息编辑器保持 `440 x 260`。
- 小心意编辑器使用 `440 x 460`，确保主题、暗号、留言和错误状态无需滚动即可显示。
- 桌面窗口尺寸由 `desktop` 桥接层控制，React 组件不直接调用 Tauri API。
- `Escape` 和取消按钮关闭面板并恢复桌宠窗口。
- 发送中禁用主题、输入框和提交按钮；失败时保留所有输入。

### 表单字段

面板标题：`送一份小心意`

字段顺序：

1. `这次想说`
2. `惊喜暗号`
3. `想对 TA 说`
4. `送出这份心意`

主题包含五个关系场景和一个通用兜底：

- `哄你开心`
- `想说抱歉`
- `生日惊喜`
- `节日心意`
- `只是想你`
- `小小惊喜`

默认主题为 `小小惊喜`。选择主题后，用该主题的默认留言填充留言框；用户已经手动编辑留言后，再切换主题需要用新模板替换当前留言，行为必须可预期且有测试覆盖。

### 输入校验

- 惊喜暗号必填。
- 去除首尾空白后长度为 `1..24` 个 Unicode 字符。
- 允许数字、英文字母和短横线，正则语义为 `[A-Za-z0-9-]+`。
- 留言选填，去除首尾空白后最多 `120` 个 Unicode 字符。
- 空留言不进入结构化载荷。
- 提交前所有长度按 Unicode 字符计数，不按 UTF-16 code unit 或字节数计数。
- 错误文案显示在对应字段附近；焦点回到第一个错误字段。

## 接收流程

### 状态机

小心意卡有四个 UI 状态：

1. `collapsed`：显示插画、主题眉题、主题主句和 `轻轻点开看看`。
2. `revealed`：显示展开卡文案、惊喜暗号、留言和 `我收下啦`。
3. `dismissing`：点击 `我收下啦` 后播放短暂退出动画。
4. `complete`：从消息队列移除，并提升下一条消息。

行为约束：

- 鼠标经过不能自动揭示或关闭。
- 只有点击折叠卡才进入 `revealed`。
- 只有点击 `我收下啦` 才进入 `dismissing`。
- 暗号揭示后持续保留，不设置自动消失时间。
- 本期不向发送方回传已查看或已收下事件。
- 普通文字消息继续使用现有鼠标经过确认和逐字气泡行为。
- 普通消息与小心意消息共享一个先进先出队列，避免同时覆盖桌宠。
- 活跃小心意卡与现有远程消息一样临时关闭点击穿透，确保可以点击。
- 打开设置、环绕菜单、状态选择器或消息编辑器时，沿用现有互斥规则，不允许多个临时界面重叠。

### 桌宠动画

- 收到小心意时优先选择带 `surprise` 标签的 motion。
- 当前资源包没有 `surprise` motion 时回退到 `message` motion。
- 两者都没有时保留当前动作，仅显示卡片。
- 发送成功后本地桌宠使用同样的 `surprise -> message -> no-op` 回退顺序。
- 内置资源包本期不新增大规模动作帧；优先复用现有 `motion-message-pair`。

### 折叠卡

- 位于 `320 x 360` 主桌宠窗口内，保持完全可见。
- 建议宽度 `244..252px`，高度约 `78..88px`。
- 卡片使用近白色实体底、细黑边和克制阴影，不使用黄色底或大面积暖色渐变。
- 插画槽约 `70 x 56px`。
- 文案区包含珊瑚红眉题、黑色主句和灰色操作提示。
- 卡片从下方轻微上移并淡入，时长不超过 `320ms`。

### 展开卡

- 建议宽度 `284px`，左右至少保留 `18px` 安全边距。
- 卡片覆盖桌宠的一部分是允许的；可读性和点击命中优先。
- 顶部使用同一插画和主题文案。
- 惊喜暗号区域使用白底、黑色虚线边框和居中大号字符，视觉上像包装内的小票或隐藏卡片。
- 留言位于暗号下方，配项目已有图标库中最接近的心意消息图标；不存在合适图标时使用已生成的插画资源，不使用文字替代。
- `我收下啦` 使用黑底白字主按钮。
- 卡片是固定可读尺寸，不随桌宠缩放设置放大，必须在 `0.6x..1.45x` 桌宠比例下保持不裁切。

### 减少动态效果

系统启用 `prefers-reduced-motion: reduce` 时：

- 禁用折叠卡入场缩放。
- 禁用展开和关闭位移动画。
- 状态切换仍立即完成，信息和操作不受影响。

## 协议设计

### 结构化内容

继续使用 `message.send` 和 `message.received`，在普通文本字段旁增加可选结构化内容：

```ts
export type SurpriseTheme =
  | "cheer"
  | "apology"
  | "birthday"
  | "festival"
  | "miss"
  | "general";

export interface SurpriseMessageContent {
  kind: "surprise";
  version: 1;
  theme: SurpriseTheme;
  secret: string;
  note?: string;
}

export type StructuredMessageContent = SurpriseMessageContent;

export interface SendClientMessage {
  type: "message.send";
  requestId: string;
  pairId: string;
  clientMessageId: string;
  text: string;
  content?: StructuredMessageContent;
}

export interface MessageReceivedServerMessage {
  type: "message.received";
  pairId: string;
  serverMessageId: string;
  fromDeviceId: string;
  text: string;
  sentAt: string;
  content?: StructuredMessageContent;
}
```

`text` 仍然必填，作为旧版本兼容兜底。小心意消息的兜底文本格式：

```text
一份小心意在等你。惊喜暗号：7482。<可选留言>
```

兜底文本同样不使用“外卖”“订单”“取件码”等物流词。

### Relay 行为

- Relay 使用共享协议解析并校验 `content`。
- `content` 缺失时按普通文字消息转发。
- `content` 存在但结构非法时拒绝该消息，返回 `malformed_message`，不转发部分内容。
- 合法 `content` 原样附加到 `message.received`。
- Relay 不解释主题文案，不保存结构化内容，不增加数据库迁移。
- 日志不得记录惊喜暗号、留言、fallback 文本或完整载荷。

### 客户端防御性解析

- 新客户端收到合法 `surprise` 内容时显示专属卡片。
- 收到未知 `kind` 或未知 `version` 时忽略结构化内容，显示 `text` 普通气泡。
- 收到已知 `kind` 但字段非法时忽略结构化内容，显示 `text` 普通气泡，不崩溃。
- 主题文案由客户端本地模板生成，Relay 不发送展示文案。

### 版本兼容

- 新客户端连接旧 Relay：旧 Relay 忽略未知 `content` 字段并转发 `text`，接收方至少看到普通消息。
- 新 Relay 连接旧客户端：旧客户端忽略 `message.received` 中的未知 `content` 字段并显示 `text`。
- 新 Relay 与新客户端：显示完整小心意卡。
- 实现前必须用现有旧解析器行为测试确认“额外字段被忽略”；若旧 Relay 会因额外字段拒绝消息，则客户端需在能力协商完成前只发送 fallback 文本。

## 模块边界

### `shared`

- 在 `shared/syncProtocol.ts` 定义结构化消息类型、校验器和解析逻辑。
- 主题值和 payload 约束属于协议；中文展示文案不进入协议。

### `server`

- `server/src/websocketRelay.ts` 只负责验证和转发结构化内容。
- 不加入产品文案、图标或 UI 逻辑。

### `sync`

- `src/sync/realtimeClient.ts` 支持发送可选 `content`，并在接收事件中透传。
- 远程消息队列改为可区分普通文字和小心意的联合类型，继续保证 FIFO。

### `message`

- 新增独立的小心意编辑器组件，复用发送结果和错误状态模式，不把主题表单塞进普通文字编辑器。
- 主题文案集中在一个纯数据模块中，发送面板和接收卡片共用，避免文案漂移。

### `ui/status`

- 新增独立接收卡片组件，不把小心意状态塞进 `PeerStatusCard`。
- 对方在线状态签与小心意卡互斥显示，小心意卡优先。

### `desktop`

- `windowCommands` 增加带受控 surface 类型的编辑器窗口调用。
- Rust 侧只接受 `message` 或 `surprise`，分别映射到固定尺寸，不接受任意前端尺寸。
- 关闭任一编辑器都恢复打开前保存的桌宠几何位置。

### `assets`

- 最终插画复制到 `src/assets/ui/surprise/` 或同等清晰目录。
- 资源文件必须是项目自制 PNG；保留设计参考和生成说明。

## 错误处理

- 未绑定：桌宠气泡提示先完成绑定。
- Relay 未连接：沿用现有连接错误提示，不打开编辑器。
- 对方离线：提示对方当前不在线，不打开编辑器。
- 暗号为空或格式非法：字段内联错误，不发送。
- 留言超长：字段内联错误，不发送。
- Relay 拒绝或网络失败：保留表单和主题，恢复提交按钮，显示可重试错误。
- 发送成功：关闭编辑器、恢复窗口、播放本地互动 motion，并在本地会话列表记录 fallback 文本。
- 接收 payload 非法：降级为普通文字气泡。

## 隐私与安全

- 惊喜暗号和留言按现有普通消息方式经 Relay 明文传输；界面和文档不宣称端到端加密。
- 不把暗号、留言或消息正文写入生产日志、测试截图文件名或遥测。
- 所有协议字段均有长度和 allowlist 校验，避免利用结构化字段绕过 `MESSAGE_TEXT_MAX_LENGTH`。
- React 只渲染文本节点，不使用 `dangerouslySetInnerHTML`。
- 不自动读取剪贴板、系统通知或第三方应用内容。

## 测试策略

### 共享协议

- 合法六主题 payload 通过校验和解析。
- 非法 kind、version、theme、secret、note 被拒绝或在接收端降级。
- Unicode 长度边界和短横线规则正确。
- 普通文字消息无回归。
- 带未知额外字段的旧消息解析行为有明确测试。

### Relay

- 新 payload 在两台已绑定在线设备间原样转发。
- 发送方收到现有 `message.delivered`。
- 非法 payload 返回 `malformed_message`，对端不收到消息。
- 日志断言不包含 secret 和 note。
- 旧式纯文字消息仍可双向转发。

### React 组件

- 环绕菜单显示 `发消息` 和 `外卖到啦`，不显示 `敲电脑` 和 `生气鼓脸`。
- 六个入口使用确认的黑白线稿透明 PNG、固定六点坐标和统一包装式按钮状态；悬停、键盘聚焦、按下和减少动态效果均有覆盖。
- 六个主题切换正确更新默认留言和 payload。
- 暗号和留言校验、发送中、失败重试、取消和 Escape 行为正确。
- 折叠卡不显示暗号。
- 点击折叠卡后才显示暗号。
- 鼠标经过不会揭示或关闭。
- `我收下啦` 才完成消息并提升队列。
- 普通消息和小心意消息混合入队时保持 FIFO。
- 未知 payload 降级为普通消息。
- 活跃卡片期间点击穿透和其他临时界面互斥正确。

### Rust/Tauri

- `message` 和 `surprise` 两种编辑器尺寸计算正确。
- 多显示器、负坐标、HiDPI 和 macOS 菜单栏工作区内居中。
- 重复打开不覆盖最初保存的桌宠几何位置。
- 关闭或失败路径都清理保存状态并恢复窗口。

### 视觉 QA

- 在 Windows debug 客户端中实测折叠、展开和关闭三种状态。
- 在 `0.6x`、`1.0x`、`1.45x` 桌宠比例下无裁切、文字重叠或按钮越界。
- 浅色和深色桌面背景上插画、卡片边界和文字可读。
- 320 x 360 主窗口内卡片不超出边界。
- 实际资源不是文字、emoji、黄色方块或通用占位图标。
- 六个环绕按钮在普通、悬停、键盘聚焦和按下状态下与确认效果图一致，并保持原有点击位置。
- `prefers-reduced-motion` 下无非必要动画。

## 验收标准

1. 环绕菜单中 `敲电脑` 已改为 `发消息`，`生气鼓脸` 已替换为 `外卖到啦`。
2. 在线且已绑定时，可选择主题、填写惊喜暗号和留言并发送。
3. 接收端先看到主题提醒，不提前显示暗号。
4. 点击卡片后显示主题展开文案、惊喜暗号和留言。
5. 卡片只在点击 `我收下啦` 后关闭。
6. 接收端没有外卖、订单、配送、取件码或平台品牌文案。
7. 图标使用确认的黑白线稿透明 PNG，不使用黄色方块、emoji 或文字替代。
8. 普通文字消息功能和现有确认行为无回归。
9. 新旧客户端或 Relay 混用时至少显示可读 fallback 文本。
10. 协议、服务器、客户端、Rust 和视觉测试全部通过。
11. 产出新的 Windows debug EXE，并完成两台客户端的真实 Relay 互通验证。
