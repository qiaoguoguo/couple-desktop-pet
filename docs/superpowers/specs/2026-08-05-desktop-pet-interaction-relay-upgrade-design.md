# 桌宠互动体验与中继默认化升级设计

## 背景

当前桌宠已经具备本地动画、右键设置、托盘、中继绑定、远程消息和导入资源包能力。本轮用户提出 5 个体验升级点：

1. 桌宠拖到桌面边缘时进入半隐藏状态，露出半个头扒在屏幕边缘。
2. 启动后不在任务栏显示软件图标，只保留托盘。
3. 中继服务部署到云服务器，exe 默认绑定中继地址，不再让用户手动输入地址。
4. 互动消息气泡文字逐字流式显示。
5. 发送消息不放在设置页中，改为点击“发送消息”操作后，在屏幕中心弹出输入框。

本设计只覆盖桌面端体验和现有 relay 服务部署，不引入账号系统、官网下载流程、支付、排行榜或 AI 生成平台。

## 目标

- 拖拽桌宠靠近屏幕左侧、右侧或顶部边缘时，自动进入“扒边半隐藏”状态。
- 半隐藏状态下使用 Q 版小人专用边缘资源，视觉上像半个头或上半身抓在屏幕边缘。
- 点击或拖动半隐藏桌宠时恢复正常显示。
- Windows 启动后不在任务栏显示主窗口图标，托盘仍可显示、隐藏、打开设置和退出。
- 客户端默认中继地址为 `http://159.75.175.47:8787`，WebSocket 地址由现有 `toWebSocketRelayUrl()` 转为 `ws://159.75.175.47:8787/ws`。
- 设置页远程互动区域只保留生成绑定码、输入绑定码、绑定、取消绑定、状态和错误提示，不显示启用复选框和中继地址输入框。
- 收到远程消息和本地互动气泡时，文字逐字出现，增加互动感。
- 左键互动菜单新增“发送消息”操作，打开屏幕中心消息输入窗口，用户输入后发送给已绑定且在线的对方。

## 非目标

- 不做公共随机匹配。
- 不做账号系统和排行榜。
- 不把远程消息发送放回设置页。
- 不为所有导入资源包强制新增边缘资源格式。
- 不做底部任务栏方向的自动半隐藏，避免和 Windows 任务栏、macOS Dock、Linux panel 冲突。
- 不在本轮做 HTTPS/WSS；没有域名时先使用裸 IP 的 HTTP/WS。
- 不做复杂聊天记录窗口，只保留当前会话列表和发送入口。

## 方案概览

采用一个小版本同时处理桌面体验和中继默认化：

- 桌面边缘吸附由 Rust/Tauri 侧读取窗口位置和当前显示器工作区，计算是否进入左、右、上三种 `edge-peek` 状态。
- 前端宠物状态新增 `edgePeek` 派生显示状态，不污染既有动作状态机的动作列表。
- 资源层新增内置 Q 版小人的三张边缘姿态资源：`left`、`right`、`top`。
- Tauri 主窗口设置 `skipTaskbar: true`，托盘继续作为系统入口。
- relay 服务部署到远程服务器 `159.75.175.47:8787`，客户端默认配置和 CSP 同步允许该地址。
- 消息输入使用第二个 Tauri 窗口，不挤占桌宠主窗口，也不在任务栏显示。
- 气泡文本渲染抽成 `TypewriterText`，用于本地气泡和远程消息气泡。

## 功能设计

### 1. 边缘半隐藏

支持边缘：

- `left`：靠近屏幕左侧，露出右半边头/手。
- `right`：靠近屏幕右侧，露出左半边头/手。
- `top`：靠近屏幕顶部，露出下半张脸或上半身扒在顶部边缘。

不支持自动底部半隐藏。底部位置继续由原有活动范围和窗口位置逻辑处理。

触发规则：

- 用户拖拽结束后，Tauri 读取主窗口外框位置、外框尺寸和当前显示器工作区。
- 如果窗口距离左/右/上边缘小于等于 `24px`，进入对应半隐藏状态。
- 半隐藏时 Tauri 把窗口移动到半出屏位置：
  - 左侧：窗口 x = 工作区左边界 - 窗口宽度的一部分，只保留可点击可见区域。
  - 右侧：窗口 x = 工作区右边界 - 可见区域宽度。
  - 顶部：窗口 y = 工作区上边界 - 窗口高度的一部分，只保留下半部分。
- 可见区域建议不少于 `84px × 96px`，保证用户能点回来。
- 进入半隐藏后保存状态到本地窗口位置文件，重启后可恢复到普通安全位置或半隐藏状态；本轮优先恢复到普通安全位置，避免启动后找不到桌宠。

退出规则：

- 点击半隐藏宠物：恢复到屏幕内，并切回原 idle 行为。
- 拖动半隐藏宠物：先恢复，再开始拖拽。
- 右键半隐藏宠物：恢复后打开右键菜单。

资源：

```text
src/assets/pets/q-girl/edge-peek/left.png
src/assets/pets/q-girl/edge-peek/right.png
src/assets/pets/q-girl/edge-peek/top.png
```

资源要求：

- 透明 PNG。
- 和当前 Q 版小人风格一致。
- 无文字、无水印、无绿色/白色背景残留。
- 画面应包含“抓住屏幕边缘”的手部或身体姿态。
- 资源只用于内置 Q 版小人；导入资源包暂不要求提供边缘姿态。

### 2. 任务栏隐藏与托盘保留

主窗口配置：

- `skipTaskbar: true`
- `transparent: true`
- `decorations: false`
- `alwaysOnTop: true`
- `resizable: false`

托盘菜单保留：

- 显示
- 隐藏
- 设置
- 退出

托盘“设置”仍通过现有 `open-settings` 事件打开主窗口并关闭点击穿透。

### 3. 默认远程中继

默认地址：

```text
http://159.75.175.47:8787
```

客户端行为：

- `defaultSettings.sync.enabled = true`
- `defaultSettings.sync.relayUrl = "http://159.75.175.47:8787"`
- 如果历史配置中的 relayUrl 是本地开发默认值 `http://127.0.0.1:8787`、`http://localhost:8787` 或空值，加载时迁移到云端默认地址。
- 如果用户曾明确保存其他非本地 relayUrl，本轮保留该值，但 UI 不再提供普通用户编辑入口。

设置页远程互动区域：

- 不显示“启用远程互动”复选框。
- 不显示“中继地址”输入框。
- 显示连接状态：
  - 未绑定
  - 已绑定
  - 连接中
  - 对方在线/离线
  - 错误提示
- 显示操作：
  - 生成绑定码
  - 输入绑定码
  - 绑定
  - 取消绑定

服务部署：

- 使用现有 `server` relay 服务。
- 远程监听 `0.0.0.0:8787`。
- 数据使用 SQLite，挂载到远端持久目录，例如 `/opt/couple-pet-relay/data/relay.sqlite`。
- 无域名阶段直接开放 8787 端口。
- 客户端 CSP 增加：
  - `http://159.75.175.47:8787`
  - `ws://159.75.175.47:8787`

部署验收：

```bash
curl http://159.75.175.47:8787/health
```

预期返回 relay 健康状态 JSON。

### 4. 消息逐字显示

新增 `TypewriterText` 组件：

- 输入完整文本、播放速度、是否启用。
- 默认速度：每 `35ms` 显示一个中文字符或一个 Unicode code point。
- 最长消息也应在合理时间内显示，速度可按长度轻微加速，避免长消息拖太久。
- 使用 `Array.from(text)` 处理 Unicode，避免拆坏 emoji 或部分组合字符。
- 当文本 id 改变时重新播放。
- 当 `prefers-reduced-motion: reduce` 时直接显示完整文本。

使用位置：

- `BubbleLayer` 的本地互动气泡。
- `RemoteMessageLayer` 的对方消息气泡。

远程消息关闭规则保持不变：

- 对方发来的消息不会因为计时器自动消失。
- 必须鼠标移入/互动确认后进入 dismiss 流程。
- 逐字显示期间也允许确认，但建议确认后延迟到当前气泡完成最小可读时间再消失。

### 5. 屏幕中心发送消息输入框

左键互动菜单新增一个操作：

- `send-message`
- 文案：`发送消息`
- 图标资源：`src/assets/ui/interaction-buttons/send-message.png`

这个操作不是宠物动画动作，不进入 `PetActionName`。它是 UI 命令：

- 点击后关闭互动菜单。
- 如果未绑定或对方不在线，显示本地气泡错误，例如“对方还不在线，稍后再发吧。”
- 如果可以发送，打开第二个 Tauri 窗口。

消息输入窗口：

- 窗口 label：`message-composer`
- 尺寸建议：`420 × 240`
- 屏幕居中。
- 置顶。
- 不显示任务栏图标。
- 可关闭。
- 不抢占桌宠主窗口状态。

窗口内容：

- 标题：`给对方发消息`
- 多行输入框，最大长度建议 `280` 字。
- 按钮：发送、取消。
- Enter 发送，Shift+Enter 换行。
- 发送中禁用按钮。
- 发送成功后关闭窗口，并在桌宠旁显示“消息已送出”的短气泡。
- 发送失败时窗口内显示错误，不清空文本。

前端通信：

- `message-composer` 窗口通过 Tauri event 向主窗口发送 `{ text }`。
- 主窗口复用现有 `handleSendMessage(text)` 发送到 realtime client。
- 主窗口将发送结果以事件回传 composer 窗口；成功关闭，失败显示错误。

设置页调整：

- 移除设置页中的消息 textarea 和发送按钮。
- 可以保留当前会话消息列表，作为调试和状态观察。

## 数据和模块边界

- `desktop`：窗口隐藏任务栏、边缘检测/吸附、打开消息输入窗口、Tauri 事件桥接。
- `pet` / `renderer`：半隐藏状态渲染，点击恢复。
- `assets`：新增边缘半隐藏 PNG 和发送消息按钮 PNG。
- `settings`：默认 relay 地址和本地配置迁移。
- `sync`：绑定按钮简化、发送消息逻辑保留、消息气泡逐字显示。
- `ui`：消息输入窗口和 typewriter 文本。

UI 组件不得直接调用 Rust 窗口 API；仍通过 `desktop/windowCommands.ts` 或明确的桥接模块调用。

## 测试要求

前端测试：

- 默认设置中 relayUrl 是 `http://159.75.175.47:8787`，sync 默认启用。
- 旧本地 relayUrl 会迁移到云端默认地址。
- `SyncPanel` 不渲染启用复选框和中继地址输入框。
- `SyncPanel` 只保留绑定相关按钮和会话列表。
- 互动菜单包含 `发送消息` 命令，点击后调用打开 composer 的回调，不触发宠物动作。
- 未绑定或离线时点击发送消息显示本地错误气泡。
- `TypewriterText` 按字符逐步显示，换 text/id 后重播，reduced-motion 下直接显示。
- `RemoteMessageLayer` 使用逐字显示且仍需 hover 确认消失。
- 边缘半隐藏状态下渲染对应 `edge-peek` 图片，点击恢复。

Rust/Tauri 测试：

- `tauri.conf.json` 主窗口包含 `skipTaskbar: true`。
- CSP 包含 `http://159.75.175.47:8787` 和 `ws://159.75.175.47:8787`。
- 边缘吸附计算：
  - 左侧阈值内进入 left。
  - 右侧阈值内进入 right。
  - 顶部阈值内进入 top。
  - 底部不进入 edge-peek。
  - 不靠边保持普通状态。
- 半隐藏后的窗口可见区域不小于约定最小值。

服务测试：

- relay 服务可用现有单元测试。
- 远端部署后 `curl http://159.75.175.47:8787/health` 成功。

## 验收标准

- 运行 exe 后任务栏不出现“情侣桌宠”窗口图标，托盘存在并可操作。
- 桌宠拖到左、右、顶部边缘后半隐藏，露出 Q 版小人扒边资源。
- 点击半隐藏桌宠能恢复。
- 设置页不要求用户输入中继地址。
- 两台机器使用默认中继地址可生成绑定码和绑定。
- 收到消息时显示对方形象和消息气泡，文字逐字出现，鼠标确认后才消失。
- 点击互动菜单中的“发送消息”后，屏幕中心出现输入窗口。
- 设置页不再承担发送消息入口。
- Debug exe 构建成功。

## 风险

- 裸 IP HTTP/WS 在公网可用性依赖服务器防火墙和云安全组开放 8787 端口。
- 没有 HTTPS/WSS 时，未来浏览器网页不能直接复用这个 relay；桌面端可以先用。
- 不同平台的 `skipTaskbar` 和托盘行为存在差异，本轮优先验证 Windows。
- Tauri 原生拖拽结束时机和窗口位置读取在多屏环境可能有边界差异，需要自动计算测试和 Windows 实测双重验证。
- AI 生成边缘姿态资源可能需要二次挑选，尤其是手抓屏幕边缘的方向感。

## 自审

- 占位检查：本文未发现占位项。
- 一致性检查：中继默认地址、CSP、设置迁移、UI 隐藏输入框保持一致。
- 范围检查：本设计聚焦桌面交互、中继默认化和 relay 部署，不包含账号、官网和排行榜。
- 歧义处理：半隐藏只做左、右、顶部；底部不做。发送消息使用第二个 Tauri 窗口，不使用主桌宠小窗口承载。
