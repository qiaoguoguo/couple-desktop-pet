# Q 版内置形象 PNG 动作帧重绘与动画导演层设计

日期：2026-08-04

状态：待用户复核后进入实施计划阶段

## 背景

当前桌宠客户端已经支持 PNG 序列帧、互动菜单、气泡、远程消息、导入资源包和基础状态机，但体验仍偏机械：动作像轮播图，缺少明显肢体动作、情绪节奏和互动仪式感。

本轮采用方案 A：重绘 PNG 动作帧 + 动画导演层。明确不尝试用现有 PNG 硬凑新动作；真实挥手、敲电脑、抱抱、撒娇等动作必须由新帧资源承担，导演层只负责组织节奏、气泡、入场、停顿和回落。

用户确认：新的内置默认形象不再使用星星睡衣小星人，改为之前生成的 Q 版长发眼镜女生形象。

参考图已保存到：

```text
docs/assets/references/q-girl-pet-reference.png
```

## 目标

1. 将默认内置形象替换为 Q 版长发眼镜女生。
2. 保持 PNG 序列帧路线，不引入 Live2D、Spine 或 v2 分层骨骼资源包。
3. 重绘一套更有肢体动作的内置动作帧，明显提升情绪价值。
4. 增加动画导演层，让动作有前摇、主动作、停顿、气泡时机、回落和远程消息场景。
5. 保持已导入旧资源包兼容，不破坏当前用户已有 `.cdpet`。
6. 后续可平滑迁移到 v2 分层动画包，但本轮不实现 v2。

## 非目标

- 不做用户上传照片自动生成资源包的完整后台链路。
- 不做骨骼绑定、部件切分、Live2D、Spine、DragonBones。
- 不做语音、AI 对话或复杂情绪人格。
- 不推翻现有设置、绑定、消息、资源包导入功能。
- 不把星星人继续作为默认展示形象。

## 新内置形象定义

默认内置包 ID 建议新增为：

```text
builtin:q-girl
```

形象特征：

- Q 版女孩，全身比例，头大身小。
- 深棕色长发，圆框眼镜，大棕色眼睛。
- 浅灰紫格纹上衣/连衣裙层次，白色宽松长裤，白色鞋。
- 表情温柔、亲近、轻微害羞。
- 动作中必须保留长发、眼镜、服装层次、白裤子这些身份特征。

星星人处理：

- 不再作为默认内置形象。
- 可以短期保留为 legacy fallback 或测试资源，避免开发期间资源缺失导致空白。
- 设置列表中优先展示 Q 版形象；是否继续暴露星星人由后续产品决定。

## 动作规格

第一期仍沿用现有 12 个动作 ID，降低代码和资源包迁移成本：

| 动作 ID | 新动作意图 | 必须出现的肢体/道具变化 |
| --- | --- | --- |
| `idle-breathe` | 安静呼吸、眨眼、头发轻摆 | 胸口/肩膀轻微起伏，眼睛眨动，发尾轻晃 |
| `idle-look` | 偷偷看用户、扶眼镜 | 头部转向，眼睛视线移动，一只手轻扶眼镜 |
| `idle-stretch` | 小伸懒腰 | 双臂伸展，身体上提，衣摆和头发回落 |
| `walk` | 小步走或小碎步挪动 | 双脚交替、身体重心左右变化，头发随动 |
| `drag` | 被拖起时轻晃 | 身体悬起，脚尖离地，手臂和头发跟随晃动 |
| `sleep` | 困倦入睡 | 眼睛闭合，身体下沉，偶尔点头 |
| `act-cute` | 撒娇卖萌 | 双手贴脸或轻握，头部倾斜，脸红加强 |
| `act-typing` | 敲电脑 | 出现小键盘/小电脑，双手敲击后抬头 |
| `act-wave` | 打招呼 | 一只手明显挥动，身体前倾 |
| `act-hug` | 求抱抱 | 双臂张开，向前小跳，期待停顿 |
| `act-pout` | 生气鼓脸 | 双臂抱胸，鼓脸，眼睛偏向一侧 |
| `act-drowsy` | 困困打盹 | 打哈欠、揉眼、点头惊醒 |

每个动作必须按分镜生成，而不是只在同一姿态上改表情。

## 帧数和资源包兼容

当前 v1 资源包固定 18 帧。为了提升内置动画连贯性，同时不破坏旧资源包，采用兼容式 v1.5：

- 旧导入包：继续支持每动作 18 帧。
- 新内置 Q 版包：优先使用每动作 30 帧。
- 推荐帧率：5 fps。
- 推荐时长：6 秒。
- Manifest 增加可选 `frameCount` / `durationMs`，未提供时按旧版 18 帧推断。
- 导入校验兼容 18 帧和 30 帧，第一期不强制所有用户包升级到 30 帧。

这样既能改善默认体验，也不会让已经导入的资源包失效。

## 动画导演层

导演层不是替代绘图，而是组织已有动作帧和 UI 反馈。

新增概念：

```ts
interface MotionScene {
  id: string;
  action: PetActionName;
  phases: MotionPhase[];
  bubbleCues: BubbleCue[];
  effects: EffectCue[];
  exitAction?: PetActionName;
}
```

第一期可用轻量配置，不需要一开始做复杂编辑器。

### 动作节奏

每个互动动作拆成：

1. 前摇：点击后快速响应，例如眨眼、轻抖、转头。
2. 主动作：播放真实动作帧。
3. 情绪停顿：关键表情停留 0.5-1 秒。
4. 回落：自然回到待机。

### 气泡时机

气泡不再总是在动作开始出现：

- `act-cute`：头歪和脸红后弹出“陪我一会儿嘛。”
- `act-typing`：敲击 1-2 秒后弹出“我也在努力敲代码。”
- `act-hug`：张开双臂后弹出“可以抱一下吗？”
- `act-pout`：鼓脸停顿时弹出“哼，快哄我。”

### 远程消息场景

收到消息时不再只是气泡：

1. 对方形象从侧边或屏幕边缘轻轻入场。
2. 播放 `act-wave` 或 `act-cute`。
3. 显示消息气泡，并保持直到鼠标滑过确认。
4. 确认后播放短回落/挥手离场。

如果对方没有导入对应 Q 版资源，则使用当前选中的对方资源包 fallback，但仍套同一个导演节奏。

## 资源生成策略

不一次性盲目生成 360 张。先做质量基准，再批量。

阶段 1：标准角色基准

- 生成 `character-base.png`，透明背景。
- 角色必须全身居中，保留长发、眼镜、灰紫格纹、白裤子、白鞋。
- 小尺寸 128px 高度下仍能读出脸和动作。

阶段 2：两组动作试产

- 先生成 `idle-breathe` 30 帧。
- 再生成 `act-cute` 30 帧。
- 通过小尺寸、连贯性、身份一致性检查后，再继续其余动作。

阶段 3：完整动作批量

- 生成剩余 10 组动作。
- 每组输出绿幕或透明 PNG。
- 本地做去绿幕、裁边、尺寸统一和 contact sheet 预览。

阶段 4：接入和验收

- 内置默认包切到 `builtin:q-girl`。
- 设置面板显示新预览图。
- 星星人不再作为默认。

## 质量标准

每组动作必须通过以下检查：

- 没有上下半截、断身体、错位、缺头发、缺眼镜。
- 每个动作至少有 2 个明显关键姿势。
- 肢体动作在 128px 高度下仍能看出意图。
- 角色身份不漂移：发型、眼镜、服装、脸型一致。
- 无绿边、无阴影底、无文字、无水印。
- 循环动作首尾能自然衔接。
- 非循环动作结束能自然回到 `idle-breathe`。

## 测试和验收

自动化测试：

- Manifest 支持 18 帧旧包和 30 帧内置包。
- 新默认包 ID 为 `builtin:q-girl`。
- 互动动作 `durationMs >= 5000`。
- 导演层能在指定时间触发气泡。
- 互动完成后回到待机。
- 远程消息确认后才消失。
- 旧 `.cdpet` 18 帧资源包仍能导入。

手工验收：

- 启动后默认显示 Q 版长发眼镜女生。
- 单击菜单选择 6 个互动动作，能看到真实肢体动作。
- 撒娇、敲电脑、挥手、抱抱、鼓脸、打盹动作意图明显。
- 待机不再僵硬，能自然呼吸、眨眼、看用户、伸懒腰。
- 消息互动有对方形象入场和确认后离场。
- 小尺寸显示仍清楚。

## 风险

- 30 帧 x 12 动作约 360 张 PNG，仓库体积会继续增加。
- AI 批量生成容易造成角色漂移，需要先试产两组动作确认质量。
- 用户照片自动生成不在本轮解决；本轮只打磨内置形象和客户端播放体验。
- 如果 30 帧资源质量不稳定，可以降级为每动作 24 帧 / 4 fps，但不低于 5 秒。

## 实施建议

推荐先做一个最小体验闭环：

1. 新增 Q 版形象目录和 manifest 兼容能力。
2. 生成并接入 `idle-breathe` 和 `act-cute` 两组 30 帧。
3. 加入导演层最小实现：气泡时机 + 动作回落。
4. 手工看效果，确认角色一致性。
5. 再批量补齐剩余 10 组动作。

这个顺序能最早发现资源质量问题，避免一次性生成大量不可用图片。
